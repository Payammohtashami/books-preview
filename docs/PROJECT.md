# کتاب درسی تعاملی سه‌بعدی — سند محصول و معماری

> نسخه ۰.۱ — پیش‌نویس برای بازبینی. پس از تأیید این سند، ساخت پروژه آغاز می‌شود.

## ۱. چشم‌انداز

اپی که کتاب‌های درسی را (PDF) نمایش می‌دهد و در بخش‌های مشخصی از صفحات، **مدل‌های سه‌بعدی تعاملی** (چرخاندن، بزرگ‌نمایی، برچسب‌ها، انیمیشن، کوییز) کنار متن نشان می‌دهد تا مفاهیم انتزاعی ملموس شوند.

**اصول:**
- آفلاین‌اول: بعد از اولین بارگذاری، همه‌چیز بدون اینترنت کار کند.
- یک کدبیس برای موبایل و دسکتاپ (PWA نصب‌پذیر).
- فارسی و راست‌به‌چپ (RTL) به‌صورت پیش‌فرض.
- محتوا از کد جدا باشد: افزودن یک درس جدید = افزودن چند فایل داده، نه تغییر کد.

## ۲. کاربران و سناریوها

| کاربر | نیاز |
|---|---|
| دانش‌آموز | خواندن صفحه‌ی کتاب، لمس نقطه‌ی تعاملی، دیدن مدل سه‌بعدی، چرخاندن، یادگیری با برچسب و کوییز کوتاه |
| معلم | نمایش مدل روی پروژکتور/دسکتاپ در کلاس، بدون نیاز به اینترنت |
| سازنده‌ی محتوا (شما) | وارد کردن PDF، علامت‌گذاری ناحیه‌ها روی صفحه، اتصال مدل سه‌بعدی به ناحیه |

## ۳. محدوده‌ی نسخه‌ی اول (MVP)

**داخل محدوده:**
1. کتاب‌خوان PDF (فهرست کتاب‌ها، باز کردن کتاب، ناوبری صفحه، زوم، ذخیره‌ی آخرین صفحه).
2. **نقاط تعاملی (Hotspot)** روی صفحه؛ با لمس/کلیک، پنل سه‌بعدی باز می‌شود.
3. **بیننده‌ی سه‌بعدی** (Three.js): چرخش، زوم، جابه‌جایی، برچسب‌های قابل‌لمس، تغییر لایه/بخش، انیمیشن ساده، تمام‌صفحه.
4. **یک درس نمونه** (۳ تا ۵ نقطه‌ی تعاملی) برای اثبات مفهوم؛ پیشنهاد: یک مبحث از علوم تجربی (مثلاً ساختار سلول یا منظومه‌ی شمسی).
5. حالت آفلاین کامل و نصب‌پذیر (PWA) روی اندروید، iOS و دسکتاپ.
6. رابط فارسی RTL، حالت روشن/تیره، اعداد فارسی.
7. **ابزار ساخت محتوا (Authoring)** ساده داخل اپ برای قرار دادن Hotspot روی PDF و ذخیره‌ی آن در فایل JSON.

**خارج از محدوده‌ی MVP:** حساب کاربری و همگام‌سازی ابری، اپ بومی استور، واقعیت افزوده (AR)، چندزبانه، فروشگاه محتوا، ساخت خودکار مدل با هوش مصنوعی.

## ۴. ویژگی‌ها (جزئیات)

### ۴.۱ کتابخانه
- کارت هر کتاب: جلد، عنوان، پایه، درصد پیشرفت، نشانگر «آفلاین آماده است».
- وارد کردن PDF از دستگاه (انتخاب فایل) و ذخیره در حافظه‌ی مرورگر (IndexedDB)؛ همچنین بسته‌ی محتوای آماده (`book pack`).

### ۴.۲ خواننده
- رندر صفحه با PDF.js، بارگذاری تنبل صفحات، بازیابی صفحه‌ی آخر.
- روی موبایل: تک‌صفحه، سوایپ؛ روی دسکتاپ: تک/دوصفحه‌ای + میان‌برهای صفحه‌کلید.
- لایه‌ی Hotspot بالای صفحه با مختصات نسبی (۰ تا ۱) تا با هر اندازه‌ی نمایش درست بماند.

### ۴.۳ بیننده‌ی سه‌بعدی
- فرمت مدل: **glTF/GLB** (فشرده با Draco/Meshopt)، هدف حجم هر مدل زیر ۲ مگابایت.
- کنترل لمسی (یک انگشت چرخش، دو انگشت زوم/جابه‌جایی) و ماوس.
- برچسب‌ها (annotations) متصل به نقاط مدل، با متن فارسی.
- حالت کم‌مصرف برای گوشی‌های ضعیف (کاهش کیفیت سایه/پیکسل‌ریتو، رندر فقط هنگام تعامل).
- اگر WebGL در دسترس نبود: تصویر ثابت جایگزین.

### ۴.۴ کوییز کوتاه (اختیاری در MVP)
- یک تا سه سؤال چندگزینه‌ای پس از هر مدل، ذخیره‌ی نتیجه محلی.

### ۴.۵ ابزار ساخت محتوا
- حالت «ویرایش»: کشیدن مستطیل روی صفحه ← انتخاب مدل ← نوشتن عنوان/توضیح ← افزودن برچسب‌های مدل.
- خروجی: `lesson.json` و فایل‌های مدل کنار هم. (در MVP ذخیره‌ی محلی و خروجی/ورودی فایل.)

## ۵. معماری فنی

**پشته:** Vite + React + TypeScript، Three.js با `@react-three/fiber` و `drei`، PDF.js، Zustand (وضعیت)، `idb` (IndexedDB)، `vite-plugin-pwa` (Workbox)، Tailwind CSS (ویژگی‌های منطقی RTL)، فونت Vazirmatn (خودمیزبان، نه CDN، برای آفلاین).

```
school-books/
├─ docs/                 # همین سند و تصمیم‌ها
├─ public/
│  ├─ icons/             # آیکن PWA
│  └─ content/           # بسته‌های محتوا (کتاب/درس/مدل)
│     └─ <book-id>/
│        ├─ book.json
│        ├─ book.pdf
│        └─ lessons/<lesson-id>/{lesson.json, *.glb}
├─ src/
│  ├─ app/               # مسیریابی، قالب، تم
│  ├─ features/
│  │  ├─ library/
│  │  ├─ reader/         # PDF + لایه‌ی hotspot
│  │  ├─ viewer3d/
│  │  ├─ quiz/
│  │  └─ authoring/
│  ├─ lib/               # storage، pdf، i18n، اعداد فارسی
│  └─ styles/
└─ vite.config.ts
```

### ۵.۱ مدل داده

```jsonc
// book.json
{ "id": "science-7", "title": "علوم تجربی هفتم", "grade": 7, "pdf": "book.pdf",
  "lessons": ["cell"] }

// lessons/cell/lesson.json
{ "id": "cell", "title": "سلول", "hotspots": [
  { "id": "h1", "page": 12, "rect": [0.12, 0.30, 0.45, 0.25],   // x,y,w,h نسبی
    "title": "ساختار سلول", "model": "cell.glb",
    "annotations": [ { "pos": [0.1, 0.4, 0.0], "text": "هسته" } ],
    "quiz": [ { "q": "...", "options": ["..."], "answer": 0 } ] }
]}
```

نسخه‌ی طرح (`schemaVersion`) در هر فایل برای مهاجرت‌های بعدی.

### ۵.۲ آفلاین
- **Service Worker (Workbox):** پیش‌کش `app shell` (HTML/JS/CSS/فونت)؛ استراتژی `CacheFirst` برای مدل‌ها و PDF؛ `StaleWhileRevalidate` برای `book.json`.
- دکمه‌ی «دانلود برای آفلاین» برای هر کتاب (کش کردن PDF و مدل‌ها پیش از نیاز) با نوار پیشرفت و نمایش حجم.
- درخواست `navigator.storage.persist()` برای جلوگیری از پاک شدن خودکار حافظه.
- نمایش وضعیت اتصال و نسخه‌ی کش؛ به‌روزرسانی با اعلان «نسخه‌ی جدید آماده است».
- نکته‌ی iOS: سهمیه‌ی ذخیره‌سازی محدودتر است؛ مدل‌ها باید سبک باشند.

### ۵.۳ عملکرد
- بارگذاری تنبل (lazy) برای Three.js و PDF.js (تقسیم کد)؛ بودجه‌ی اولیه زیر ~۲۵۰ کیلوبایت gzip برای شِل.
- رندر Three فقط در صورت نیاز (`frameloop="demand"`)، محدودکردن `dpr`.
- Web Worker برای PDF.js.

### ۵.۴ RTL و دسترس‌پذیری
- `lang="fa" dir="rtl"`، ویژگی‌های CSS منطقی (`ms/me/ps/pe`)، آیینه‌کردن فلش‌ها، اعداد فارسی، خط‌فاصله‌ی نیم‌فاصله (ZWNJ).
- محتوای PDF خودش ممکن است جهت متفاوت داشته باشد؛ جهت ناوبری صفحه‌ها از `book.json` (`direction`) خوانده می‌شود.
- متن جایگزین برای مدل‌ها، ناوبری با صفحه‌کلید، تضاد رنگ AA، پشتیبانی از `prefers-reduced-motion`.

## ۶. حریم خصوصی و مجوزها
- بدون ردیابی و بدون ارسال داده؛ همه‌چیز محلی.
- **مجوز محتوا:** PDF کتاب‌های درسی و تصاویر آن‌ها ممکن است مالکیت ناشر (در ایران: سازمان پژوهش و برنامه‌ریزی آموزشی) داشته باشد. برای استفاده‌ی شخصی/آموزشی مشکلی نیست، اما برای انتشار عمومی اپ همراه با PDF باید مجوز گرفته شود. مدل‌های سه‌بعدی باید اورجینال یا با مجوز آزاد (CC0/CC-BY) باشند و منبع‌شان ثبت شود.
- اپ به‌صورت پیش‌فرض PDF را فقط روی دستگاه کاربر نگه می‌دارد و بارگذاری عمومی ندارد.

## ۷. آزمون و کیفیت
- آزمون واحد (Vitest) برای مختصات hotspot، اعتبارسنجی schema (Zod)، ذخیره‌سازی.
- آزمون end-to-end (Playwright): باز کردن کتاب، لمس hotspot، حالت آفلاین (قطع شبکه).
- چک‌لیست دستی: ۳۶۰px، لمس، RTL، اندروید Chrome، iOS Safari، دسکتاپ Chrome/Edge/Firefox.
- Lighthouse PWA و کارایی ≥ ۹۰.

## ۸. معیارهای پذیرش MVP
1. نصب روی اندروید، iOS (افزودن به صفحه‌ی اصلی) و ویندوز/مک بدون خطا.
2. پس از یک بار بارگذاری، با قطع کامل اینترنت: کتاب باز شود، hotspot کار کند، مدل سه‌بعدی نمایش داده شود.
3. مدل سه‌بعدی روی گوشی میان‌رده ≥ ۳۰ فریم بر ثانیه.
4. افزودن یک hotspot جدید با ابزار ساخت، بدون تغییر کد.
5. همه‌ی متن‌ها فارسی و بدون خطای جهت‌دهی.

## ۱۰. ریسک‌ها

| ریسک | کاهش |
|---|---|
| حجم PDF و مدل‌ها در حافظه‌ی موبایل | فشرده‌سازی glTF، کش انتخابی، نمایش حجم |
| محدودیت‌های iOS در PWA | آزمون زودهنگام روی iOS، حجم کم |
| عملکرد WebGL روی گوشی‌های ضعیف | رندر در صورت نیاز، کیفیت تطبیقی، تصویر جایگزین |
| تهیه‌ی مدل سه‌بعدی باکیفیت | شروع با یک درس؛ مدل‌های CC0 یا ساخت در Blender |
| مجوز محتوا | بخش ۶؛ انتشار فقط بدون PDF ناشر |

## ۱۱. پرسش‌های باز (برای تصمیم قبل از ساخت)
1. درس نمونه دقیقاً کدام باشد؟ (PDF همان کتاب را بعداً در پوشه قرار دهید.)
2. مدل‌های سه‌بعدی را خودتان می‌سازید (Blender) یا از منابع آزاد برداریم؟
3. آیا روی میزبانی (مثلاً Netlify/Cloudflare Pages) منتشر شود یا فقط نصب محلی؟
